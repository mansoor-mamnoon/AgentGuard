# LLMFirewall + Claude Desktop

Claude Desktop connects to MCP servers you configure in `claude_desktop_config.json`. Every server listed there gets direct access to your tools and files. LLMFirewall sits in between: Claude talks to LLMFirewall, and LLMFirewall talks to the real server — enforcing allowlists, blocking injection payloads, and redacting secrets before they reach the model.

## Install

```bash
pip install llmfirewall
```

Verify:

```bash
llmfirewall --version
```

## Config file location

| OS | Path |
|---|---|
| macOS | `~/Library/Application Support/Claude/claude_desktop_config.json` |
| Windows | `%APPDATA%\Claude\claude_desktop_config.json` |
| Linux | `~/.config/Claude/claude_desktop_config.json` |

Create the file if it does not exist.

## Minimal example — filesystem server

Replace the upstream server directly with LLMFirewall. Claude sees the same tool names; the proxy enforces the rules silently.

```json
{
  "mcpServers": {
    "safe-filesystem": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem /Users/me/project",
        "--allow-tools", "read_file,list_files",
        "--policy", "/Users/me/project/policies/default.yaml"
      ]
    }
  }
}
```

What this does:

- `read_file` and `list_files` are the only tools Claude can call — `write_file` is stripped from the tool list before Claude sees it.
- Any file whose content scores above the injection threshold is blocked; Claude gets a clear error rather than a compromised response.
- API keys and tokens found in file content are redacted to `[REDACTED]` before the model sees them.

## Multiple servers behind one firewall policy

```json
{
  "mcpServers": {
    "safe-filesystem": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem /Users/me/project",
        "--allow-tools", "read_file,list_files",
        "--policy", "/Users/me/project/policies/default.yaml"
      ]
    },
    "safe-git": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-git /Users/me/project",
        "--allow-tools", "git_log,git_diff,git_show",
        "--policy", "/Users/me/project/policies/default.yaml"
      ]
    },
    "safe-sqlite": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "python -m mcp_server_sqlite /Users/me/data.sqlite",
        "--allow-tools", "query,list_tables",
        "--policy", "/Users/me/project/policies/strict.yaml"
      ]
    }
  }
}
```

## Strict mode — read-only, no exceptions

Use `policies/strict.yaml` (generated by `llmfirewall init`) for contexts where you want zero write access:

```json
{
  "mcpServers": {
    "docs-only": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem /Users/me/docs",
        "--policy", "/Users/me/docs/policies/strict.yaml"
      ]
    }
  }
}
```

## Write confirmation mode — human-in-the-loop

For write tools you want to keep available but confirm before executing:

```json
{
  "mcpServers": {
    "guarded-filesystem": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem /Users/me/project",
        "--allow-tools", "read_file,list_files,write_file",
        "--require-write-confirm"
      ]
    }
  }
}
```

With `--require-write-confirm`, any tool classified as a write operation is blocked unless the call includes `"confirm": true` in its params. This forces an explicit confirmation step in your Claude workflow.

## Audit log

To keep a full record of every blocked and allowed action:

```json
{
  "mcpServers": {
    "safe-filesystem": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem /Users/me/project",
        "--allow-tools", "read_file,list_files",
        "--audit-log", "/Users/me/.llmfirewall/audit.jsonl"
      ]
    }
  }
}
```

Each line of `audit.jsonl` is a JSON event:

```json
{"ts": "2026-05-16T10:23:01Z", "event": "block", "method": "tools/call", "reason": "Tool output from 'read_file' contains injection payload (score=0.446)", "id": 3}
{"ts": "2026-05-16T10:23:02Z", "event": "allow", "method": "tools/call", "id": 4}
{"ts": "2026-05-16T10:23:03Z", "event": "sanitize", "method": "tools/call", "what": "Secret values redacted from 'read_file' output", "id": 5}
```

## Initialise a policy for your project

```bash
cd /Users/me/project
llmfirewall init
```

This creates `policies/default.yaml` and `policies/strict.yaml` in the current directory, and prints the exact JSON snippet to paste into `claude_desktop_config.json`.

## Restart Claude Desktop

After editing `claude_desktop_config.json`, quit and relaunch Claude Desktop. The proxy starts fresh with each new conversation.
