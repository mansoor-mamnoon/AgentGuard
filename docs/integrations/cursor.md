# LLMFirewall + Cursor

Cursor supports MCP servers through a JSON config file. Wrapping each server with LLMFirewall means the model's tool access is gated even when Cursor automatically invokes tools during edits, completions, or agent tasks.

## Install

```bash
pip install llmfirewall
```

## Config file location

| Scope | Path |
|---|---|
| Project (per-repo) | `.cursor/mcp.json` in the workspace root |
| Global (all projects) | `~/.cursor/mcp.json` |

The project-level file takes precedence and is the recommended location — check it into version control so every team member gets the same guardrails.

## Minimal example

```json
{
  "mcpServers": {
    "safe-filesystem": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem ${workspaceFolder}",
        "--allow-tools", "read_file,list_files",
        "--policy", "${workspaceFolder}/policies/default.yaml"
      ]
    }
  }
}
```

`${workspaceFolder}` expands to the absolute path of the open project. Using it in both `--upstream` and `--policy` means the config is portable: clone to any machine and it works.

## Full project setup

```json
{
  "mcpServers": {
    "safe-filesystem": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem ${workspaceFolder}",
        "--allow-tools", "read_file,list_files",
        "--policy", "${workspaceFolder}/policies/default.yaml",
        "--audit-log", "${workspaceFolder}/.llmfirewall/audit.jsonl"
      ]
    },
    "safe-git": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-git ${workspaceFolder}",
        "--allow-tools", "git_log,git_diff,git_show",
        "--policy", "${workspaceFolder}/policies/default.yaml"
      ]
    }
  }
}
```

## Protecting a database server

```json
{
  "mcpServers": {
    "safe-db": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "python -m mcp_server_sqlite ${workspaceFolder}/data.sqlite",
        "--allow-tools", "query,list_tables",
        "--policy", "${workspaceFolder}/policies/strict.yaml"
      ]
    }
  }
}
```

`strict.yaml` (generated by `llmfirewall init`) disallows all write tools. `query` is read-only by policy; even if a retrieved row contains "DROP TABLE employees", the injection guard blocks the response before the model sees it.

## Quiet mode for CI / headless Cursor

If you run Cursor in a scripted or headless environment, suppress per-request audit chatter with `--quiet`:

```json
{
  "mcpServers": {
    "safe-filesystem": {
      "command": "llmfirewall",
      "args": [
        "proxy",
        "--upstream", "mcp-server-filesystem ${workspaceFolder}",
        "--allow-tools", "read_file,list_files",
        "--quiet",
        "--audit-log", "${workspaceFolder}/.llmfirewall/audit.jsonl"
      ]
    }
  }
}
```

Audit events still go to the file; nothing goes to stderr.

## Initialise a policy

```bash
cd /your/project
llmfirewall init
```

This generates `policies/default.yaml` and `policies/strict.yaml` and prints the exact `.cursor/mcp.json` snippet. Commit both files to version control.

## Reloading

After editing `.cursor/mcp.json`, use **Cursor → Settings → MCP** (or restart Cursor) to reload server connections. The proxy starts fresh per session.
